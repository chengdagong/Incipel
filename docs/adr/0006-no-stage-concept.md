# 不设「阶段 / 成熟度」概念:作品即其内容

早期版本由剧本内容派生一个有序的创作阶段(灵感 → 世界观 → 人物 → 大纲 → 分场),
经 `deriveStage` 计算后注入 system prompt,并显示在对话顶栏、文档面板与作品列表
(`packages/shared/src/stage.ts`、各 UI 的「当前阶段」行)。现已彻底删除,且不以任何
形式回归:**系统在任何地方都不持有「创作进展 / 成熟度 / 完成度」这一概念。**

理由是创作本身非线性——用户随时可以改剧本的任意部分。把它呈现为一段有先后的阶梯,
既不符合真实的写作过程,也容易被误读为存在顺序约束(尽管那个派生阶段从不真正限制
编辑,它只是个展示标签)。删掉它,呈现就回到唯一诚实的事实:一部作品就是它当前的内容。

## 推论(留给后来人,尤其 v1.1 做导出的人)

- **任何功能都对「现有内容」直接动作,不引入成熟度门槛。** 导出(Fountain / PDF,
  移出 v1,见 system-design §15)有什么导什么,哪怕剧本里只有一句 logline,也照导不误;
  **不**加 `hasScenes` 之类的前置判断或「内容太少,确定要导出吗」之类的拦截。
- **不要因为某个功能想知道「这本走到哪了」就把阶段或任何有序进展概念捡回来。** 若确有
  需要,在用到的那一处就地派生一个具体、单一用途的判断即可,不要做成全局共享的状态或类型。
- **作品列表里的「最近更新时间」是附带元数据,不构成进展概念**,与本决定不冲突:它讲的是
  「何时改的」,不是「写到哪一步」。
