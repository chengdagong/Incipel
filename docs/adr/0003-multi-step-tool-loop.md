# 模型每轮多步生成:工具调用后再产出总结文本

「织幕」一轮的模型调用走 Mastra `Agent.stream()` 的多步 tool use:工具带一个 **ack-only 的 `execute`**(只返回 `{ ok: true }`、不碰剧本),并设 `maxSteps`。剧本的实际改动仍在 `run.ts` 消费 `tool-call` 时由 `apply.ts` 完成——`execute` 不应用剧本,它唯一的作用是让 agent 拿到工具结果后**再生成一步**,而那一步才产出给用户的自然语言总结(`TEXT_MESSAGE_*`)。

之所以这么做:单步时,模型一旦进入「调工具」模式,常常**只发工具调用、不产任何文本**,聊天里就是一个空的助手气泡。不同模型不一,Claude 常带一句确认、GPT/Gemini 多为空。我们在 Claude Sonnet 4.5 上实测 **0/5** 全为空(prompt 硬约束也搬不动);改多步后,同样 5 个强接管措辞 **5/5 既写了内容又给了简短总结**。

## Consequences

- 有「剧本改动」的轮通常约 **2 次模型生成**(第 1 步工具、第 2 步总结);`maxSteps` 上界设为 8,既容纳模型分几步写内容,又防它一直调工具不结束。
- **不要**把 apply 挪进 `execute`、也**不要**删掉 `maxSteps`——前者会与 `run.ts` 的应用重复,后者会把「空回复」带回来。
- 被否决的替代:① 纯 prompt 要求每轮说话(实测 0/5 无效);② `say` 工具(单步、更省,但非确定性);③ UI 层回退(用户明确不要)。
